# 领域文档

本仓库采用 Map 驱动的递归披露布局，逐级导航领域知识和架构决策。

## 根入口

- 领域上下文：根目录 `CONTEXT-MAP.md`
- 架构决策：根目录 `ADR-MAP.md`

Agent 不得绕过 Map 无差别扫描所有 Context 或 ADR。

## Context 读取

1. 从根目录 `CONTEXT-MAP.md` 开始。
2. 每个 `CONTEXT-MAP.md` 只列直接子 Map 或直接叶子 `CONTEXT.md`。
3. 沿当前任务相关的目录分支递归读取。
4. 到达叶子 `CONTEXT.md` 后，读取其中的术语、边界和不变量。
5. 跨领域任务可以读取多个相关分支，但不得加载无关分支。

## ADR 读取

1. 从根目录 `ADR-MAP.md` 开始。
2. 每个 `ADR-MAP.md` 只列当前目录的直接 ADR 和直接子 Map。
3. 具体决策使用 `0001-*.md` 格式，一个文件记录一项决策。
4. 只打开与当前任务相关的 ADR。
5. 新增、移动或删除 ADR 时，必须更新其直接父目录的 `ADR-MAP.md`。

## Map 维护

- Map 不得跨级列出孙级内容。
- 每个条目必须包含名称、相对路径和范围摘要。
- 目录结构变化时，只更新发生变化的直接父 Map。
- Map 链接失效或内容漂移时必须明确报错。

## 统一词汇与决策冲突

规格、ticket、测试、重构提案和用户报告应使用相关 `CONTEXT.md` 定义的词汇。缺少术语时，先确认现有上下文是否覆盖；确属空缺时再通过领域建模补充。拟议工作与既有 ADR 冲突时必须显式指出，不得静默覆盖。
